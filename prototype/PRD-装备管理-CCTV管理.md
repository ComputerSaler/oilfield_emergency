## 第1章 概述

### 1.1 背景

海外油田现场安保体系依赖多种感知设备，CCTV（闭路电视监控）是固定区域监控的核心手段。当前 CCTV 设备由第三方视频平台统一管理，应急指挥平台需要：

1. **聚合展示** CCTV 设备的基础信息（名称、位置、在线状态等）
2. **补充标记** 设备的精确经纬度坐标，用于 GIS 地图联动展示
3. **快速跳转** 到实时监控中心查看视频画面

本模块是平台「装备管理」体系的一部分，与 A类无人机、高点摄像头等设备管理功能平级。

### 1.2 目标用户

- **应急指挥中心值班人员**：需要快速查看全营地 CCTV 分布和在线状态，定位监控盲区
- **营地安保负责人**：需要管理本营地的 CCTV 台账，标记设备精确位置
- **GIS 大屏操作员**：需要在地图上查看 CCTV 的覆盖范围

### 1.3 核心功能

| 功能模块 | 说明 |
|---|---|
| 设备台账列表 | 展示所有 CCTV 设备的名称、营地、站点、服务器、IP、在线状态、经纬度 |
| 多维度筛选 | 按设备名称、营地、站点、在线状态、IP地址筛选 |
| 位置标记 | 为 CCTV 标记精确经纬度坐标（平台扩展字段） |
| 位置查看 | 在地图弹窗中查看已标记的设备位置 |
| 跳转监控中心 | 一键跳转到实时监控中心查看该设备的视频画面 |

### 1.4 红线约束

⚠️ **只读铁律**：CCTV 设备的主数据（名称、营地、站点、服务器、IP、在线状态）全部来自第三方视频平台，平台**严禁**提供增删改入口。唯一可编辑的字段是**经纬度**（平台扩展字段）。

⚠️ **防误判铁律**：设备在线状态的唯一来源是中台 WebSocket 推送，平台不做任何本地判定（不 ping、不心跳）。当 WS 连接中断时，所有设备进入「未知态」（全行置灰），严禁批量判定为离线。

## 第3章 核心规则

### 3.1 只读铁律

**规则内容**：CCTV 设备的以下字段为三方系统只读字段，平台**严禁**提供任何编辑入口（包括但不限于表单、弹窗、批量导入）：

- 设备名称
- 所属营地
- 站点
- 服务器
- IP地址
- 在线状态

**唯一例外**：经纬度坐标为平台扩展字段，可通过「标记位置」功能编辑，数据保存在平台数据库，不同步回三方系统。

**违反后果**：如果平台允许编辑只读字段，会导致平台数据与三方系统不一致，且三方系统的下一次数据推送会覆盖平台的修改，造成数据混乱。

### 3.2 防误判铁律

**规则内容**：设备在线状态的判定必须遵循以下三条规则：

1. **单一数据源**：在线状态的唯一来源是中台 WebSocket 推送的 `online` 字段，平台不做任何本地判定（不 ping 设备 IP、不发送 RTSP 心跳、不根据最后上线时间推测）
2. **WS 断线处理**：当平台与中台的 WS 连接中断时，所有 CCTV 设备进入「未知态」，UI 表现为：
   - 在线状态列显示灰色减号 `--`
   - 整行文字淡化（opacity: 0.5）
   - **严禁**将设备批量标记为离线
3. **WS 恢复处理**：WS 重连成功后，中台会推送全量设备状态，前端用最新推送覆盖本地状态

**违反后果**：本地判定在线状态会导致「WS 断线 → 平台误判所有设备离线 → 触发大量误告警」的严重事故。

### 3.3 状态单一来源

**规则内容**：在线状态的数据流向为：

```
第三方视频平台 → 中台聚合服务 → WebSocket 推送 → 前端展示
```

平台前端是数据流的**终点**，不是**源头**，严禁反向修改状态。

### 3.4 位置扩展规则

**规则内容**：CCTV 的经纬度坐标为平台扩展字段，遵循以下规则：

1. **存储位置**：保存在平台数据库（`cctv_device_location` 表或类似），不同步回三方系统
2. **初始值**：如果三方系统推送的 CCTV 数据中包含经纬度字段，优先使用三方值；否则初始为空（`undefined`）
3. **覆盖规则**：平台标记的经纬度优先级高于三方推送值，即使三方后续推送了坐标，也不覆盖平台已标记的值
4. **删除规则**：平台不提供「清除位置」功能，只能重新标记（覆盖旧值）

## 第4章 数据结构

### 4.1 CCTV 设备数据模型

```typescript
interface CctvDevice {
  // ========== 三方系统只读字段 ==========
  id: string                    // 设备唯一标识符（主键）
  name: string                  // 设备名称，如"东南角监控01"
  campId: string               // 营地ID
  campName: string             // 营地名称，如"Agadem营地"
  siteName: string             // 站点名称，如"井场A""宿舍区"
  serverName: string           // 服务器名称（NVR/DVR），如"NVR-01"
  ipAddress: string            // IP地址，如"192.168.1.100"
  online: boolean              // 在线状态：true=在线，false=离线
  
  // ========== 平台扩展字段 ==========
  location?: {                 // 经纬度坐标（可选，未标记时为 undefined）
    latitude: number           // 纬度，范围 -90 ~ 90
    longitude: number          // 经度，范围 -180 ~ 180
  }
}
```

### 4.2 字段来源标注

| 字段 | 来源 | 可编辑 | 说明 |
|---|---|---|---|
| id | 三方系统 | ❌ | 全局唯一，用于 WS 增量更新匹配 |
| name | 三方系统 | ❌ | |
| campId | 三方系统 | ❌ | |
| campName | 三方系统 | ❌ | |
| siteName | 三方系统 | ❌ | 营地下的子区域 |
| serverName | 三方系统 | ❌ | NVR/DVR 设备名称 |
| ipAddress | 三方系统 | ❌ | 设备 IP 地址 |
| online | 三方系统（WS推送） | ❌ | 唯一来源是中台 WS，平台不做本地判定 |
| location | **平台扩展** | ✅ | 通过「标记位置」功能编辑，保存到平台数据库 |

### 4.3 location 字段详细说明

**数据类型**：
```typescript
location?: {
  latitude: number    // 纬度，保留 6 位小数，范围 -90 ~ 90
  longitude: number   // 经度，保留 6 位小数，范围 -180 ~ 180
}
```

**三种状态**：
1. **未标记**：`location` 为 `undefined`，表格中经纬度列显示 `--`
2. **已标记**：`location` 为 `{ latitude, longitude }` 对象，表格中显示「纬度, 经度」
3. **三方推送**：如果三方系统推送的数据中包含经纬度，初始填充该值；但一旦平台标记过，平台值优先级更高

**浮窗规格**：

- 初始位置：屏幕右上角，距边缘 24px
- 可拖动：鼠标在标题栏按住拖动，释放后固定在新位置

**浮窗布局**：

```
┌─ 视频浮窗 ──────────────────────────┐
│ 📹 设备名称                    ✕    │ ← 标题栏（可拖动）

│                                    │
│       [视频播放区域 16:9]           │ ← 根据状态显示不同占位
│                                    │
├────────────────────────────────────┤
│ 设备名称： 东南角监控01              │
│ 所属营地： Agadem营地                │

│ 服务器：   NVR-01                   │
│ IP地址：   192.168.1.100            │
│ 在线状态： [在线 / 离线]             │
└────────────────────────────────────┘
```

**视频状态机**（复用 PRD-实时监控中心-视频监控 的 Slot 状态定义）：

| 状态 | 视觉表现 | 触发条件 | 说明 |
|---|---|---|---|
| 加载中 | 转圈图标 + "视频加载中..." | 点击在线设备后的初始状态 | 原型阶段模拟 1s 后进入播放态 |
| 播放中 | 占位画面 + "视频流播放中...（原型阶段占位）" | 加载成功 | 黑色背景 `#0a0a0a` |
| 设备离线 | 断开图标 + "设备已离线" + "无法获取视频流" | 点击离线设备 / WS 推送设备掉线 | 深色背景 `#141414` |
| 加载失败 | 警告图标 + "视频加载失败" + "请检查网络或稍后重试" | 超时或网络错误 | 原型阶段不模拟此状态 |

**交互规则**：

| 操作 | 前置条件 | 行为 |
|---|---|---|
| 点击「实时监控」 | 无 | 打开浮窗，初始位置右上角；根据设备在线状态进入对应视频状态 |
| 拖动标题栏 | 浮窗已打开 | 鼠标按下时跟随移动，释放后固定在新位置 |
| 点击右上角 × | 浮窗已打开 | 关闭浮窗，断开视频连接（模拟） |
| WS 推送设备掉线 | 浮窗正在播放该设备 | 视频状态切换到「设备离线」，保留设备信息 |
| WS 推送设备恢复在线 | 浮窗处于「设备离线」状态 | 自动重新加载视频（进入「加载中」→「播放中」） |
| 点击已打开浮窗的设备 | 浮窗已显示该设备 | 无操作（同一设备不重复打开；若需支持多路同看，应前往实时监控中心-视频监控页） |

**注意事项**：
- 浮窗一次只显示一路视频。如果浮窗已打开，再次点击其他设备的「实时监控」，则替换为新设备
- 浮窗关闭时应断开视频连接（原型阶段通过清空 `currentVideoDevice` 模拟）
- 离线设备点击后照常打开浮窗，窗内显示「设备已离线」占位，**不禁用按钮**

2. 调用接口保存（接口待确认，参考路径 `PATCH /api/cctv/:id/location`）
3. 保存成功后：
   - 弹出 `message.success('位置已保存')`
   - 关闭弹窗
   - 刷新列表数据（或前端直接更新对应行的 `location` 字段）

**地图区域（V1 原型阶段）**：
- 显示灰色占位区域，提示"地图功能待集成"
- 后续版本需集成 GIS 地图组件，支持：
  - 显示设备当前位置（如果已标记）
  - 拖拽地图标注点更新经纬度输入框
  - 输入框变化时同步移动地图标注点

### 5.6 WS 断线处理

**触发条件**：平台与中台的 WebSocket 连接中断（检测逻辑由全局 WS 管理模块负责）

**UI 表现**：
1. **在线状态列**：所有行的在线状态显示灰色减号 `--`（不显示「在线」或「离线」）
2. **整行样式**：所有行文字淡化（`opacity: 0.5`）
3. **全局提示**：页面顶部显示警告条（`a-alert type="warning"`）：
   ```
   ⚠️ 与服务器连接中断，设备状态无法更新，正在尝试重连...
   ```

**WS 恢复处理**：
1. WS 重连成功后，中台推送全量 CCTV 设备状态
2. 前端用最新推送数据**完全覆盖**本地状态
3. 移除警告条，恢复正常显示

**严禁行为**：
- ❌ WS 断线时，将所有设备标记为离线
- ❌ WS 断线时，根据最后更新时间推测设备状态
- ❌ WS 恢复后，保留断线期间的本地状态（必须用服务端全量覆盖）

## 第6章 异常处理

### 6.1 WS 断线

**触发条件**：
- 平台与中台 WebSocket 连接中断
- 检测方式：WS `onclose` 事件触发，或心跳超时（30秒无响应）

**处理流程**：
1. **UI 降级**：全行置灰，在线状态显示 `--`，顶部显示警告条（见 §5.6）
2. **自动重连**：每隔 5 秒尝试重连，最多尝试 10 次
3. **重连成功**：中台推送全量状态，前端完全覆盖本地数据，移除警告条
4. **重连失败**：10 次尝试后仍失败，警告条变为错误条：
   ```
   ❌ 无法连接到服务器，请检查网络或联系管理员
   ```

### 6.2 空数据处理

**场景1：列表初次加载为空**
- 表格显示空状态：「暂无 CCTV 设备数据」
- 不显示筛选栏（或筛选栏置灰）

**场景2：筛选结果为空**
- 表格显示空状态：「未找到符合条件的 CCTV 设备」
- 保持筛选栏可用，用户可修改条件重新查询

### 6.3 经纬度越界校验

**场景**：用户在位置弹窗中输入超出范围的经纬度

**校验规则**：
- 经度范围：`-180 ~ 180`
- 纬度范围：`-90 ~ 90`
- 精度：保留 6 位小数

**处理流程**：
1. 输入框实时校验（`a-input-number` 的 `min`/`max` 属性）
2. 超出范围时输入框显示红色边框
3. 点击「保存」按钮时，如果值越界，弹出错误提示：
   ```
   message.error('经纬度超出有效范围，请检查后重试')
   ```
4. 不关闭弹窗，允许用户修正

### 6.4 接口异常处理

**场景**：列表数据接口超时或返回 5xx 错误

**处理流程**：
1. 表格显示空状态：「数据加载失败」
2. 显示「重试」按钮，点击后重新请求接口
3. 如果连续 3 次失败，提示用户联系管理员

## 第7章 非功能需求

### 7.1 性能要求

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 列表初次加载 | < 2s | 从接口请求到表格渲染完成 |
| 筛选响应 | < 500ms | 点击「查询」到表格刷新 |
| 位置弹窗打开 | < 300ms | 点击按钮到弹窗完全展示 |
| WS 消息处理 | < 100ms | 收到 WS 推送到 UI 更新 |

### 7.2 兼容性要求

**浏览器支持**：
- Chrome 90+
- Edge 90+
- Firefox 88+

**屏幕分辨率**：
- 最小屏幕宽度：1366px
- 推荐分辨率：1920x1080

### 7.3 响应式设计

- 表格列宽固定（不自适应），总宽度约 1280px
- 如果屏幕宽度不足，表格出现横向滚动条
- 操作列固定在右侧（`fixed: 'right'`），滚动时始终可见

### 7.4 原型说明

**原型阶段特殊处理**：

1. **Mock 数据**：使用本地 Mock 数据（约 20 条 CCTV 设备记录），不调用真实接口
2. **WS 连接**：不实现真实 WebSocket 连接，所有设备状态为静态（不会动态变化）
3. **视频浮窗**：视频区域显示占位画面，提示"视频流播放中...（原型阶段占位）"；模拟加载 1 秒后进入播放态；不拉取真实视频流
4. **地图组件**：位置弹窗内的地图区域显示灰色占位，提示"地图功能待集成"
5. **接口调用**：「保存位置」按钮点击后，直接弹出成功提示，不发送真实请求

**原型目标**：
- 验证 UI 布局和交互流程
- 确认字段完整性和展示规则
- 为开发团队提供视觉和交互规范

## 第8章 待确认清单

### 8.1 接口文档确认

**需要对接的接口**：

| 接口 | 路径（暂定） | 说明 | 优先级 |
|---|---|---|---|
| 获取 CCTV 列表 | `GET /api/cctv` | 返回所有 CCTV 设备数据 | P0 |
| 获取营地列表 | `GET /api/camps` | 用于筛选栏下拉框 | P0 |
| 保存设备位置 | `PATCH /api/cctv/:id/location` | 保存经纬度到平台数据库 | P0 |
| WS 推送协议 | `ws://xxx/topic/cctv-status` | 实时推送设备在线状态 | P1 |

**待确认内容**：
- 接口的完整路径和参数格式
- 返回数据的字段名称（是否与 §4.1 数据模型一致）
- WS 推送的消息格式（单个设备更新 or 批量更新）

### 8.2 视频流接口确认

**当前假设**：
- 视频流协议：HLS（.m3u8）
- 拉流地址由设备 ID 动态拼接（原型阶段不实现真实拉流）

**待确认内容**：
- 视频流协议：HLS / RTSP / WebRTC / FLV
- 拉流地址格式：`/api/video/stream/:deviceId` 或其他
- 离线设备是否需要调用接口判断，还是仅依赖 WS 推送的在线状态

### 8.3 字段扩展需求

**当前字段清单**（8个）：
- 设备名称、营地、站点、在线状态、IP地址、服务器、经纬度、操作

**潜在扩展字段**（待客户确认是否需要）：

**确认方式**：与客户现场演示原型，收集反馈

### 8.4 GIS 地图组件选型

**待确认内容**：
