```
┌─ 右侧事件区（360px，高度 = 窗口高度 - 48px）────────────────────────────┐

│ └────────────────────────────────────────────────────────────────────┘ │
│ ┌─ 事件状态漏斗（高 140px）──────────────────────────────────────────┐ │
│ │  实时存量：                                                          │ │
│ │   待评级  →  事件生效  →  处置中                                    │ │
│ │  今日终态：                                                          │ │
│ │   已关闭  N  │  已转应急  N  │  已撤销  N                           │ │
│ └────────────────────────────────────────────────────────────────────┘ │
│ ┌─ 事件列表（flex，剩余高度）────────────────────────────────────────┐ │
│ │  [待处理] [进行中] [今日已结束]                                      │ │

│ │  ──────────────────────────────────────────────────────────────── │ │
│ │  [Ⅲ] SJ-20260927-0002  围界入侵事件     ●一般                      │ │
│ │       Sokor  ·  手工录入  13:10  处置中 任务 0/2 已通过             │ │
│ └────────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3.1 事件 KPI 看板

| 指标卡 | 数据来源 | 告警规则 |
|---|---|---|
| 待评级 | 当前状态=`pending_level` 的事件数 | 大于 0 时橙色背景 |
| 进行中 | 状态=`active / in_progress` 的事件数 | 无特殊告警 |
| 今日新增 | 今日 0 点后创建的事件数 | 无 |
| 今日关闭 | 今日 0 点后进入已关闭或已撤销的事件数 | 无 |
| 超时 | 超过评级时限仍未评级的事件数 | 大于 0 时红色背景 |

数值通过 WebSocket 增量更新，每 5 秒刷新一次。今日计数在每日 0 点重置。

### 3.2 事件状态漏斗

漏斗分为上下两部分，与预警漏斗结构对称：

**上半部分（实时存量，3 节点）：**

```
待评级  [N]  →  事件生效  [N]  →  处置中  [N]
        ↕ 中位停留时长（过去 24h）
```

- 三个节点一一对应事件的三个非终态：`pending_level / active / in_progress`
- 节点间显示过去 24 小时内，事件在该状态下停留的中位时长（格式：`中位 X 分钟`）
- 「已转应急」是终态，只在下半部分计数，不进入实时存量（2026-09-27 评审修订）
- 「处置中」节点下方附小字：`任务 已通过 N / 共 M`（所有处置中事件的任务汇总）

**下半部分（今日终态计数，3 格）：**

| 今日已关闭 | 今日已转应急 | 今日已撤销 |
|---|---|---|
| N | N | N |

今日 0 点重置。

### 3.3 事件列表（3 个 Tab）

**待处理 Tab：** 状态为 `pending_level` 的事件，按创建时间倒序，超时事件置顶并标红

**进行中 Tab：** 状态为 `active / in_progress` 的事件，按等级降序（Ⅰ优先）；处置中事件第二行显示任务汇总进度

**今日已结束 Tab：** 今日进入 `closed / transferred / cancelled` 的事件，按结束时间倒序

**列表行双行布局：**
- 第一行：等级色块（Ⅰ红/Ⅱ橙/Ⅲ黄/Ⅳ蓝/未评级灰）+ 事件编号 + 标题 + 紧急度色点
- 第二行：营地 + 来源（来自预警编号 或 手工录入） + 相对创建时间 + 状态标签 + 辅助信息

列表最多展示 50 条；新条目动画插入顶部（100ms fade-in + slide-down）；终态条目淡出移除（200ms fade-out）。

点击任意一行 → 打开事件详情覆盖层（§4）。

## 4. 事件详情覆盖层

### 4.1 设计原则说明

> **为什么大屏事件覆盖层的操作范围受限？**
>
> 大屏的主要使用场景是「多人围屏决策」和「态势感知驾驶舱」，而非一线操作台。对比 PC 后台：
> - **观看距离**：大屏通常距离操作人 1.5–3 米，精细表单操作（如填写多步验收说明、管理多条并行任务）在大屏上体验差且容易出错
> - **操作对象**：大屏前通常站立多人，可能有领导、安保人员同时在场；这个场景下最高价值的操作是「快速定级」「发起应急建议」「审批应急建议（签发启动令或驳回）」——这三类决策动作
> - **责任清晰**：将重操作（处置任务创建和管理）保留在 PC 后台，避免大屏随意创建任务导致责任边界模糊
>
> 因此大屏覆盖层采用「全信息查看 + 三类关键决策操作」的设计，处置任务的增删改走 PC 后台。

### 4.2 覆盖层布局

与 PC 端事件详情页三栏结构相同，差异见 §2 的四处对比：

```
┌─ 事件详情覆盖层（全屏，覆盖在大屏之上）──────────────────────────────────────────┐
│ [← 返回驾驶舱]  SJ-20260927-0001  无人机入侵威胁  [●紧急] [Ⅱ级] [待评级]          │  顶部（48px）
├──────────────────────┬──────────────────────────────────┬───────────────────────┤
│ 左侧面板（240px）    │ 中央区域（flex）                  │ 右侧面板（360px）      │
│ 可折叠              │                                   │                        │
│ 基本信息            │ ┌─ 态势地图（上，flex）──────────┐│ [概要][证据][处置]     │
│ 来源预警列表         │ │ 事件位置标记（菱形）            ││ [时间线][上报]         │
│                      │ │ 周边摄像头 / 我方无人机         ││                        │
│                      │ │ 反无当前目标（可关闭图层）      ││ 只读内容展示           │
│                      │ └─────────────────────────────────┘│ （处置 Tab 内任务只读） │
│                      │ ┌─ 处置任务看板（下，240px）─────┐│                        │
│                      │ │ 任务列表（只读，仅查看进度）     ││                        │
│                      │ └─────────────────────────────────┘│                        │
├──────────────────────┴──────────────────────────────────┴───────────────────────┤
│ 底部操作栏（64px）：按状态仅显示以下 3 类关键决策操作                              │
│ 待评级（有 P-04 权限）: ────────────────────── [查看分级标准]  [确认等级]         │
│ 事件生效 / 处置中，无待审批建议（有 P-09 权限）: ────── [提交应急启动建议]         │
│ 事件生效 / 处置中，有待审批建议（有 P-10 权限）: ── [驳回建议] [签发应急启动令]    │
│ 有待审批建议但无 P-10 权限: 显示只读提示「应急启动建议待组长审批」               │
└─────────────────────────────────────────────────────────────────────────────────┘
```

**大屏覆盖层内不可用的操作（均须在 PC 后台完成）：**
- 撤销事件
- 直接关闭事件
- 创建/修改处置任务
- 提交处置任务验收 / 驳回
- 标记上报完成
- 导出

**点击来源预警编号（左侧面板 / 概要 Tab）：**
- 不跳转路由（跳路由会离开驾驶舱），在事件覆盖层**之上**再叠一层预警研判面板（复用 `PRD-大屏-事件感知处置-预警.md` §5.6 的覆盖层组件）
- 预警研判面板的返回按钮文案改为「← 返回事件 SJ-xxx」，关闭后回到原事件覆盖层，保留事件覆盖层的 Tab 与滚动位置
- 来源预警此时已是「已升级」终态，研判面板**只读**：不显示底部操作栏，其余 Tab 与图层正常查看；「关联」Tab 显示来源事件编号链接，点击即关闭预警面板回到事件覆盖层
- 叠层最多两层（事件 → 预警）；预警面板内的「关联事件」链接点击即关闭预警面板回到事件覆盖层，不再继续叠层

### 4.3 操作按钮规格

- 最小高度 48px（PC 后台为 32–36px），适配大屏触摸和远距操作
- 「确认等级」直接复用 PC 端确认等级弹窗（`PRD-事件管理-工作台.md` §5.5）：弹窗内单选等级（必选，默认不预选）、定级说明选填；仅按钮高度与字号按大屏规格放大，交互不另做
- 「提交应急启动建议」弹出摘要填写弹窗，字段同 PC 端，文字输入框适配大屏（字号放大至 16px）
- 「签发应急启动令」弹出二次确认弹窗，确认文案加粗显示「此操作将立即启动应急响应，无法撤回」

## 5. 中央态势地图 — 事件图层

在原预警 PRD §5.5 态势地图的基础上，新增事件相关图层。

### 5.1 事件标记样式

| 属性 | 规格 |
|---|---|
| 形状 | 菱形（与预警圆形明确区分） |
| 尺寸 | 20px 固定屏幕尺寸 |
| 颜色 | 与等级对应：Ⅰ级深红 / Ⅱ级橙 / Ⅲ级黄 / Ⅳ级蓝 / 未评级灰 |
| 动效 | 进行中事件：外圈 2 秒脉冲扩散；已关闭事件：无动效，标记透明度降至 40% |
| 标签 | hover 显示：事件编号 + 标题 + 状态 |
| 点击 | 打开事件详情覆盖层 |

预警圆形标记（已有）与事件菱形标记可同时显示，相互叠加时事件菱形在上层。

### 5.2 新增图层控制

在原预警 PRD 的图层控制按钮组中，新增：

| 图层 | 默认状态 | 说明 |
|---|---|---|
| 事件位置（进行中） | **开启** | 显示状态为 `pending_level / active / in_progress` 的事件菱形 |
| 事件位置（已结束） | **关闭** | 显示今日已关闭/已转应急的事件，透明菱形，用于复盘 |

图层控制状态通过 localStorage 在本会话内持久化，页面刷新后恢复上次选择。

### 5.3 预警与事件的地图关联

当事件来源于预警升级时：
- 预警圆形标记按终态规则**移出地图**（沿用预警 PRD §5.5 「终态预警点移出地图」），不做降饱和度保留
- 事件菱形标记独立展示；若与其他活跃预警点地图坐标重叠，横向偏移 8px 避免完全重叠
- 点击事件菱形打开事件详情覆盖层

## 6. 数据更新规则

与预警侧保持一致的 WebSocket 链路规则（复用原 PRD §5.2 的规范）：

| 规则 | 说明 |
|---|---|
| REST 快照 | 大屏初始加载时拉取全量事件数据 |
| WS 增量更新 | 事件状态变更、新事件创建实时推送到大屏 |
| 重连全量覆盖 | WS 断线重连后，拉取全量快照覆盖本地缓存 |
| 离线判定 | 3 个心跳周期（15 秒）无响应，顶栏显示「数据可能不是最新」黄色提示条 |

KPI 数字和漏斗数据每 5 秒通过 WS 更新一次，列表条目实时插入/淡出。

## 7. 边界情况

| 场景 | 处理 |
|---|---|
| 无任何事件 | 事件区整体显示「暂无事件」插图 + 说明文字，KPI 全为 0 |
| 事件无位置坐标 | 地图上不显示该事件的菱形标记，列表中正常显示；地图标记计数角标不含此事件 |
| 大屏用户无 P-04 确认等级权限 | 「确认等级」按钮不渲染，底部操作栏留空 |
| 大屏用户无任何决策权限 | 底部操作栏不显示任何按钮，显示「在 PC 后台进行操作」提示文字 |
| 事件详情覆盖层打开时 WS 推送该事件更新 | 局部刷新（不关闭覆盖层），状态标签和时间线自动更新；若事件进入终态则在覆盖层顶部显示终态提示条，文案按终态分别为「事件已关闭，不可再操作」「事件已转应急，不可再操作」「事件已撤销，不可再操作」 |
| 底部操作栏始终显示操作范围提示 | 操作栏左侧常驻灰色小字「处置任务、关闭、撤销等操作请在 PC 后台进行」，提示非决策操作的入口 |
